# 课程数据完整性

## 产品需求说明书

依据 README 的词汇、听力、阅读、翻译关卡结构，每个课程模板中的题目引用必须能在对应内容包找到，避免关卡打开后没有题目。生成器和已提交数据同时修复，重新生成不能再次引入问题。读写3词汇关按每组 5 词生成全部课程，不得固定截为 4 组，丢掉第一单元新增的 10 个词。词汇数量、唯一 ID 与选择题答案索引也须一致。

## 接口文档

无 HTTP 接口。现有 JSON 结构不变，听力、阅读、翻译引用沿用内容包真实 ID：`listening:cet4_l_01`、`reading:cet4_r_01`、`translation:cet4_t_01`，六级同理。`mock_exam:` 是游戏运行时组卷入口，无独立题目文件；`rw3_*` 引用指向词汇或对应单元。

新增 `scripts/validate_data.py`，`validate_data(root: Path) -> list[str]` 返回发现的错误；命令行有错误返回非零退出码。它校验课程引用与关键数据约束，不代替完整 JSON Schema 校验或教材内容审校。`build_all.py` 最后运行此校验。

## 测试

`python3 -m unittest discover -s tests -v` 检查真实数据、生成后的模板、缺失引用、重复 ID、错误计数和越界答案；`python3 scripts/validate_data.py` 检查当前提交数据。修复后需重新执行旁边游戏的 `npm run build`，将更新后的模板打包到 `public/data`。
